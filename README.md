# kikuhr — 社内異動支援AI

社内の異動候補を、**根拠つきで**提示するツールの PoC。
AIは候補の発見と根拠の提示までを担当し、**異動の決定は人が行う**という前提で設計している。

**[解説動画を見る](https://kinuwaki.github.io/kikuhr/)** — 仕様の全体像（字幕・倍速つき）

---

## 使い方

```bash
# CLI — 依存ゼロで動く
python3 src/run_poc.py

# UI — 人事担当者に見せる用
python3 -m venv .venv
.venv/bin/pip install streamlit
.venv/bin/streamlit run src/app.py

# 検証 — 教科書・動画の数値が実装と一致するか
python3 src/test_claims.py
python3 src/test_embedding.py

# 任意 — スキル名の表記ゆれを吸収する（2GBのモデルを落とす）
.venv/bin/pip install sentence-transformers
```

## 設計

### 1. 保護属性を構造的に分離する

`schema.py` で `FEATURE_FIELDS` と `AUDIT_ONLY_FIELDS` を別の定数として定義している。
性別・年齢はデータとしては持つが、マッチングの入力には流さず、公平性検査でのみ参照する。
**規約ではなく構造で守る。**

### 2. ハードフィルタとスコアを混ぜない

満たさなければ候補にならない条件（等級・必須資格・転居可否・異動可否）は、
スコアではなくルールで落とす。スコアに混ぜると「他が高ければ転居不可の人が上位に出る」。

**除外理由は全件記録する。** 「なぜ推薦されなかったか」を説明できないシステムは
人事では使えない（本人開示請求・労組対応）。

### 3. スコアの計算

```
必須充足率 = mean(min(1, 本人習熟度 / 必要習熟度))    # 必須スキルのみ
スキル適合 = 0.75 × 必須充足率 + 0.25 × 歓迎充足率

if 必須充足率 < SKILL_FLOOR:  除外                    # ゲート（既定 0.30）

各スコアを実測分布で標準化してから合成する
加重和 = 0.33×スキル + 0.19×評価 + 0.19×希望
       + 0.14×経路 + 0.09×育成 + 0.06×つながり
総合   = 加重和 × (0.40 + 0.60 × 必須充足率)          # 減衰
```

| スコア | 定義 |
|---|---|
| スキル適合 | 必須と歓迎は別フィールドで持つ（歓迎で必須を埋め合わせない） |
| 評価適合 | コンピテンシー別評価と要求水準の適合。**未同意・未評価は中立0.5** |
| 本人希望 | 一致 1.0 / 方向違い 0.35 / **未記入 0.5**（未記入を不利にしない） |
| 異動経路 | 部署間の集約統計。最頻の異動先を1.0とする正規化 |
| 育成機会 | 平均ギャップ1.0を最良とする山形。完全充足は0.55 |
| 人的つながり | 異動先にいる過去の同僚の人数。**つながりが無ければ0.0** |

| 必須充足率 | 総合スコア |
|---|---|
| 0% / 25% | ゲートで除外 |
| 50% | 0.394 |
| 100% | 0.608 |

### 4. 加重和でよい理由、正規化が要る理由

**加重和は妥協ではない。** 小標本では重みの最適化がほとんど価値を持たないことが
知られている（Dawes 1979, *American Psychologist* 34(7), 571–582）。固定重みは
自由度を消費しないので過学習しない。社内異動は年間の成立件数が数百件規模で、
この領域にあたる。Learning to Rank への移行は、学習パラメータ1つにつき
概ね1,000件が目安なので時期尚早。

**ただし正規化しないと重みが効かない。** 値域を 0..1 に揃えるだけでは足りず、
分布の形が違うと設定した重みと実効的な重みがずれる。

| スコア | 設定重み | 修正前の実効 | 修正後 |
|---|---|---|---|
| スキル適合 | 33% | **8%** | **32%** |
| コンピテンシー | 19% | **41%** | **19%** |

スキル最重視の設定なのに、実際は**コンピテンシーが順位を支配していた**。
実測分布で z 標準化して解消した（単調変換なのでスコア内部の順序は保たれる）。
合成方法を凝るより、この正規化を直す方が効く。

重みの相対的な大小には根拠がある。**自己申告で操作できるシグナル（本人希望）と、
推定でノイズの多いシグナル（つながり）は、検証可能なシグナル（スキル・評価）より軽くする**
（[Milli, Pierson & Garg, arXiv:2305.17428](https://arxiv.org/abs/2305.17428)）。

### 5. 公平性検査は比率だけで判定しない

4/5ルール（parity ratio < 0.8）だけで判定すると、**小標本では実体のない偏りを検出する**。
年代と実力が無相関なデータでも、seed により ratio が **0.20〜0.78** まで暴れることを確認した。
これを毎回「要調査」と報告すると担当者は警告を無視し、本物のバイアスを見逃す。

判定は次の **AND**。

1. parity ratio < 0.8（実務上の影響が大きい）
2. Bonferroni補正後の p値 < 0.05（偶然では説明しにくい）

検定は Fisher の正確確率検定（小標本対応・外部依存不要、scipyとの一致を確認済み）。

| | 補正前 | 補正後 |
|---|---|---|
| 誤報率（無相関データ） | 15% | **5%** |
| 検出力（実バイアス注入） | — | **80%** |

補正後の5%は有意水準0.05に見合う値。**検査を入れただけで安心してはいけない。**
既知の答えを持つデータで、検査そのものを検証すること。

### 6. スキル名の表記ゆれ

実データではスキル名が必ず揺れる。正規化（NFKC・小文字化・記号除去）と、
埋め込みによる意味的類似度の2段構え。モデルは `multilingual-e5-large` を
**ローカル実行**するので社内データを外部APIに送らない。

**コサイン類似度をそのまま使ってはいけない。** E5系は無関係な語でもコサインが0.8前後出る。
素朴に `(cos+1)/2` で写すと「英語」と「簿記」が0.93になり、
**Pythonができる人が営業職に推薦される**。

| | コサイン |
|---|---|
| 無関係ペア（12語・66ペアの実測） | 最小0.728 / 中央0.798 / 最大0.878 |
| 同義ペア | 0.879〜0.963 |

**無関係の最大と同義の最小がほぼ接しており、単一の閾値では分離できない。**
誤同一視の方が実害が大きいので安全側に倒し、弱い同義（法人営業↔B2B営業）は
拾えないことを既知の限界として記録している。この基準値は**モデル固有**。

## 評価データの使い方

人事評価は**コンピテンシー別評価**を職務適合の判定に使う。守っている制約は3つ。

1. **総合評価点は使わない** — 総合点でのランキングは異動支援ではなく選別。
   `Employee` に総合点のフィールドを持たせていない
2. **本人同意が無ければ参照しない** — `eval_consent` が False なら評価を使わない
3. **評価が無い人を不利にしない** — 中立の 0.5。ゼロにすると異動直後の社員が
   構造的に候補から外れる

評価は処遇決定のために集めたデータなので、**利用目的の確認が必要**。
バイアス固定化のリスクもあるため、公平性検査は評価を入れた状態で必ず回すこと。

詳細は [`reports/design.md`](reports/design.md)。

## サンプルデータの組織構造

部署構成は **Daigasグループ（大阪ガス）の公開情報**が土台。
**社員データはすべて架空**（乱数生成）で、実データは含まない。

| セグメント | 部署 | 配属比率 |
|---|---|---|
| 国内エネルギー | ガス製造・エンジニアリング / 電力 / エナジーソリューション / ネットワーク | 46% |
| 海外エネルギー | 資源・海外 | 2% |
| ライフ&ビジネスソリューション | 都市開発 / 情報システム / ケミカル | 42% |
| コーポレート | 経営企画 / 事業創造 / DX企画 / 人事 / 財務 / 資材 | 10% |

配属比率は有報の従業員数に合わせている。部署数で均等割りすると部署の多い
コーポレートが最大勢力になり、「少人数部署への異動」が再現できない。

**スキル定義は事業内容からの推定**で、社内の正式な分類ではない。
実運用では社内のタレントマネジメント分類に差し替えること。

出典: [新機構表（2026年4月1日付）](https://www.osakagas.co.jp/company/press/pr2026/1798913_60968.html) ／
有価証券報告書 第208期 ／ Daigasグループ 人的資本レポート2025

## 再実装する人へ

- **順序を間違えない** — 埋め込みや深層学習から入らない。ルールと単純な類似度で組んで、
  まず人事担当者に見せる。「この候補はおかしい」という反応が、どんな精度指標よりも価値がある
- **データ量が二桁足りない** — 論文のPJFモデルは大量の求人データが前提。
  数百人規模で深層学習しても過学習するだけ
- **正規化を軽視しない** — 合成方法を凝るより、各スコアの分布を揃える方が効く
- **スコアだけでは使えない** — 適合スキル・不足・本人希望との整合を言葉で出して、
  はじめて道具になる
- **公平性は最初から入れる** — 雇用分野のAIは EU AI Act でハイリスクに分類されている。
  適用は2027年12月2日に延期されたが、Annex III 4項(b)は「**昇進**」を名指ししており
  社内異動は対象。準備期間が延びただけ
- **AIは決定しない** — 候補の発見と根拠の提示まで。この境界を曖昧にすると、
  技術的な問題が一気に人事上の問題に変わる
